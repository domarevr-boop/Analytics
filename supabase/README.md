# Supabase V5

Этот каталог содержит только активный backend-контур V5. Исторические миграции и функция V4/CX сохранены в `legacy-v4/` и не участвуют в `supabase db push`.

## Защита окружения

- Разрешена только ветка `v5/*` и worktree с именем `Analytics-v5`.
- Project ref зафиксирован в `scripts/assert-v5-environment.mjs` и сверяется с `.env.local` и `supabase/.temp/project-ref`.
- `.env.local`, CLI-link metadata и ключи не коммитятся.
- Удалённые миграции запускаются только через `npm run db:v5:push`, а не прямой `supabase db push`.
- Перед link/push необходимо отдельно убедиться, что проект V4 не выбран.

## Активная миграция

`migrations/20260906000000_v5_foundation.sql` создаёт:

- закрытые схемы `app`, `ingest`, `core`, `analytics`;
- роли приложения и кабинетные разрешения;
- реестр 12 источников;
- партии, исходные файлы, сырые строки, ошибки и события импорта;
- версионированный каталог методик;
- приватный bucket `v5-import-sources`;
- RLS и минимальные health/access RPC.

Миграция не переносит рабочие данные и не меняет формулы. Обработка и публикация конкретного источника добавляются отдельными миграциями после проверки этого фундамента.

## Применение

1. Выполнить `npx supabase login` локально; токен не добавлять в репозиторий.
2. В этом worktree выполнить `npx supabase link --project-ref <V5_PROJECT_REF>` и ввести пароль БД V5 локально.
3. Выполнить `npm run db:v5:guard`.
4. Просмотреть план изменений через `npm run db:v5:dry-run`.
5. Только после проверки выполнить `npm run db:v5:push`.

Локальный `supabase start` пока недоступен, потому что Docker на машине не установлен.
