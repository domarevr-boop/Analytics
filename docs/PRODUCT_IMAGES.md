# Изображения товаров Analytics MVP

**Статус:** канонический контракт получения изображений.

## Идентификатор

- Основным ключом изображения является `WB ID` (`wb_sku`).
- Артикул продавца не используется для CDN-запроса без подтверждённой связи с `WB ID`.
- Если значение не является положительным числом, интерфейс сразу показывает нейтральный плейсхолдер.
- Поля `nm_id`, `Артикул WB` и `Артикул (WB)` импортируются как `wb_sku`.
- Если товар уже существует по артикулу продавца, новый импорт обязан обновить у него `wb_sku`, а не завершаться после первого совпадения SKU.

## Источники

Для первого изображения карточки используется последовательность:

1. ранее подтверждённый URL из локального кэша;
2. `images.wbstatic.net/c246x328/new/{range}/{nmId}-1.jpg`;
3. `images.wbstatic.net/c516x688/new/{range}/{nmId}-1.jpg`;
4. `images.wbstatic.net/big/new/{range}/{nmId}-1.jpg`;
5. резервный адрес `wbbasket.ru`.

`range` рассчитывается как нижняя граница десятитысячного диапазона `nmId`.

## Поведение интерфейса

- Изображения загружаются лениво и декодируются асинхронно.
- При ошибке автоматически проверяется следующий URL.
- Успешный URL сохраняется по `WB ID` в `localStorage`, максимум для 1000 товаров.
- Ответ изображения дополнительно кэшируется штатным HTTP-кэшем браузера.
- Если все источники недоступны, остаётся стабильный нейтральный плейсхолдер без скачка разметки.

## Ограничение

Без корректного `WB ID` гарантированно получить изображение карточки нельзя. Новые импорты и справочники должны сохранять связь артикула продавца с `wb_sku`, когда источник предоставляет оба идентификатора.

Если товар был создан до исправления связи SKU → WB ID, необходимо повторно импортировать файл с обоими идентификаторами. После этого связь сохраняется постоянно и повторный импорт для изображений не требуется.
