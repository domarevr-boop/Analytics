## Приоритет 1 — контроль корректности v4.0

- [ ] Проверить `CR заказа` на уровнях категории, склейки и артикула; итог кабинета уже считается корректно.
- [ ] Сверить страницу «Воронка» с Dashboard на одинаковом периоде и одинаковых фильтрах.
- [ ] Добавить автоматическую диагностику покрытия после импорта: ожидаемые даты, кабинеты и отсутствующие метрики источника.
- [ ] Провести контрольную ручную валидацию CX-словаря на размеченной выборке и зафиксировать precision/recall основных тем.

## Приоритет 2 — наблюдаемость и интерфейс

- [ ] Выполнить утверждённую [поэтапную унификацию дизайн-системы](DESIGN_SYSTEM_MIGRATION.md): общий слой → пилот «Рынок» → визуальная приёмка → перенос по семействам страниц → очистка старых стилей.
- [ ] Добавить мониторинг качества CX: доля классифицированных отзывов, доля оценочных совпадений, неизвестные формулировки и изменения после публикации словаря.
- [ ] Добавить экспорт таблицы тем и выбранной детализации без выгрузки полного массива отзывов во frontend.
- [ ] Проверить доступность, пустые состояния и адаптивность всех вкладок CX.
- [ ] Унифицировать типографику нижних графиков Dashboard.

## Приоритет 3 — данные и производительность

- [ ] Добавить единый месячный источник планов ДРР и рекламного бюджета.
- [ ] Реализовать следующий этап local-first масштабирования: выборки по периоду, индексы `product_id + date`, кэш агрегатов Dashboard и виртуализацию длинных таблиц.

## Правило обновления

- Новая незавершённая работа добавляется сюда с проверяемым результатом.
- Завершённая задача удаляется отсюда и, если меняет возможности версии, кратко фиксируется в документе версии.
- Формула, архитектура хранения или общий UI-паттерн обновляются одновременно с соответствующим каноническим документом из `docs/INDEX.md`.
