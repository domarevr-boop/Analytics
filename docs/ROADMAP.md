# Roadmap Analytics MVP

Проверено: **6 сентября 2026**. Production — **V4**, активная подготовка — **V5**.

Roadmap содержит только незавершённую работу. Принятые результаты фиксируются в version-документах; этапы, зависимости, проверки и откат V5 описаны в [V5_MIGRATION_PLAN](V5_MIGRATION_PLAN.md).

## V5 — ближайший этап: backend-фундамент

- [ ] Владелец создаёт отдельный Supabase-проект V5 и локально задаёт его URL/anon key без передачи секретов в Git или чат.
- [ ] Зафиксировать идентификаторы V4/V5 окружений и автоматическую защиту от применения V5-команд к V4.
- [ ] Спроектировать и создать чистые схемы источников/партий, core-справочников и analytics без запуска исторической V4/CX-цепочки как bootstrap.
- [ ] Добавить private Storage исходных файлов, атомарный статус публикации партии, ошибки строк и идемпотентность.
- [ ] Ввести минимальные роли viewer/importer/admin и кабинетные ограничения RLS.
- [ ] Сформировать контрольный пакет V4 и fixtures, затем выбрать и перенести пилот «Рынок» без изменения формул.

Порядок последующих страниц предварительный и требует уточнения ежедневной важности владельцем: Конкуренты → География → CX hardening → Точки входа → Поисковые запросы → Воронка/реклама → Рентабельность → Планирование → Главная/товар → Отчётность.

## Правило обновления

- Новая незавершённая работа получает проверяемый результат и контур V4/V5.
- Завершённая задача удаляется отсюда и при необходимости фиксируется в документе версии.
- Формула, хранение, общий UI-паттерн, документ, навык или агентская конфигурация обновляются вместе с профильным документом и строкой [реестра](INDEX.md).
