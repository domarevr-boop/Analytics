# Поисковые запросы WB

Проверено: **16 сентября 2026**. V4 использует локальный набор; V5 имеет принятый серверный import/read-контур и server-only страницу за feature flags.

## Источник и зерно

- Источник — `.xlsx` «Поисковые запросы WB», общий рыночный отчёт без кабинета и товарной идентичности.
- Обязательные поля: дата, поисковый запрос, количество запросов, предмет, переходы в карточку, корзины и заказы.
- Канонический ключ: `date + lower(trim(query)) + category`; пустой предмет становится «Без предмета», повтор ключа заменяется последней строкой.
- Контрольный `Лето (2).xlsx` локально распознан как 14 659 канонических строк без дублей, 2 088 запросов, 72 предмета, период 19 июля — 1 сентября 2026 года. Содержимое файла не записывается в Git.

## Импорт V5

- Только `.xlsx` до 25 MiB и 500 000 строк; разбор выполняется `read-excel-file` в отдельном browser Web Worker.
- Исходник сохраняется в private Storage, SHA-256 обеспечивает идемпотентность, строки передаются чанками до 500.
- Сервер повторно проверяет ISO-даты, непустые подписи, неотрицательные целые объёмы и неотрицательные числовые средние/конверсии.
- Публикация атомарна. Ошибка любой строки отклоняет партию, текущая версия не меняется. Admin-rollback раскрывает предыдущую опубликованную версию без физического удаления фактов.
- `Лето (2).xlsx` постоянно опубликован в dev V5 без отклонений: 14 659 строк за 19.07–01.09.2026. Browser-приёмка подтвердила 3 016 агрегированных ключей, KPI, графики, карту Top‑250, фильтр «Люстры» до 367 ключей и серверную пагинацию 2/8 без V4-fallback.

## Серверная страница

- Фильтры: период, предмет и подстрока нормализованного запроса.
- KPI: запросы, переходы, заказы и оценка суммы; сравнение использует одноимённые поля предыдущего периода источника.
- Два bounded дневных ряда: весь срез и выбранный запрос.
- Карта использует Top-250 запросов по частотности; X — запросы, Y — `CR заказа`, размер — оценка суммы, цвет — относительный класс конкуренции.
- Таблица агрегируется по `query + category`, сортируется на сервере, возвращает 50 строк на страницу и общий счётчик; один RPC не возвращает более 1 000 строк.

## Формулы и связи

- `CR корзины = Σ корзины / Σ переходы в карточку × 100`.
- `CR заказа = Σ заказы / Σ корзины × 100`.
- `Рост = (Σ requests − Σ requests_previous) / Σ requests_previous × 100`; при нулевой базе и положительном текущем значении — 100%.
- `Товары = max(products)` внутри запроса и периода.
- `Потенциал = log10(requests + 1) × (100 − min(CR заказа, 100)) / log10(products + 10)` — диагностический индекс, не прогноз.
- `Оценка суммы = заказы × средний чек рынка за ту же дату`. Чек берётся из текущей серверной версии «Рынка»; для previous используется дата со сдвигом на включительную длину выбранного периода.
- Доля по штукам = заказы доступных кабинетов из текущих «Точек входа», где раздел содержит «поиск», делённые на заказы поискового среза. При текстовом фильтре запроса доля не показывается.
- Денежная доля не рассчитывается до серверного переноса финансовой атрибуции: оценку рынка нельзя выдавать за выручку продавца.
