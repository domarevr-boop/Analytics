# Воронка и реклама V5

Проверено: **14 сентября 2026**. Этап: исправленный source-aware серверный контур реализован; синтетический remote rollback-smoke и локальный аудит реального XWay-файла проходят. Рабочая публикация и browser-приёмка ещё не выполнены.

## Фактический V4-контракт

- Воронка хранится в общем локальном `DailyMetrics` по ключу `date + product_id`: `impressions`, `clicks`, `carts`, `orders`, `ordered_amount`.
- Реклама XWay обновляет непересекающиеся поля того же ключа: `ad_impressions`, `ad_clicks`, `ad_orders`, `ad_spend`.
- Повторный импорт заменяет только распознанные поля и только для присутствующих пар `date + product`; отсутствующая колонка не должна обнулять ранее загруженное поле.
- Товар разрешается внутри кабинета по seller SKU, WB SKU и алиасам. V5 обязана использовать общий import-driven resolver.
- Формулы страницы считаются из агрегированных сумм: `CTR = clicks / impressions`, `CR корзины = carts / clicks`, `CR заказа = orders / carts`, `CR показ → заказ = orders / impressions`, `средний чек = ordered_amount / orders`.

## Контрольный backup

Команда `npm run backup:v4:inspect-funnel -- "<путь-к-backup.json>"` потоково извлекает только `metrics`, товары и журнал импортов, а затем выводит агрегированные счётчики без строк отчётов.

Для `analytics-v4-backup-2026-09-06.json` подтверждено:

- 178 301 уникальная строка `date + product`, повторов ключа и потерянных ссылок на товары нет;
- воронка: 174 818 строк, 1 016 товаров, период 07.07.2025–01.09.2026;
- итоги воронки: 1 230 801 155 показов, 101 377 382 перехода, 7 785 446 корзин, 1 697 400 заказов, 3 077 128 603 ₽ заказано;
- реклама: 1 959 строк, 88 товаров, период 01.07–04.08.2026;
- журнал: 22 успешных импорта WB-воронки и 14 успешных импортов XWay.

Нарушения соседних этапов (`clicks > impressions`, `carts > clicks`, `orders > carts`) присутствуют в 13 010 / 174 / 1 289 строках. Они не исправляются при переносе: сначала нужно определить, вызваны ли они частичными импортами, разным покрытием колонок или семантикой источника.

## Принятое исправление XWay

В V4 заголовок `Заказы, руб` сопоставляется полю `ad_orders`, а `Заказы, шт` — временному `xway_orders_qty`, которое не записывается в `DailyMetrics`. Затем `ad_orders` используется как количество заказов в формуле `CPO = ad_spend / ad_orders`.

Backup подтверждает денежную семантику: сумма `ad_orders` равна 28 362 791, и в 1 056 строках она выше общего числа заказов товара. Это не допустимый счётчик рекламных заказов. V5 не должна переносить эту ошибку как серверный контракт.

14 сентября 2026 владелец утвердил:

1. `ad_orders_qty` из `Заказы, шт` как знаменатель `CPO = ad_spend / ad_orders_qty`;
2. отдельное `ad_ordered_amount` из `Заказы, руб` для денежной атрибуции и `ДРР = ad_spend / ad_ordered_amount × 100`;
3. старое V4-поле `ad_orders` считать только денежной суммой и переносить в `ad_ordered_amount`; количество из backup не восстанавливать и не подставлять. Для исторического CPO требуется повторный импорт XWay-исходника.

Контрольный `Xway_data.xlsx` содержит обе колонки, `Расход, руб.`, дату и оба артикула. Локальный аудит без передачи исходника наружу подтвердил 1 472 канонические строки за 01–23.06.2026, все пять рекламных метрик и отсутствие некорректных чисел. Parser агрегирует повторные строки `дата + товар`, сохраняет фактические Excel-даты и не добавляет отсутствующие в файле колонки в patch. Unit-тест отдельно защищает русские и английские заголовки, разделение штук и рублей и знаменатель CPO.

## Целевая граница

Используются независимые source-aware версии WB-воронки и XWay с nullable patch-полями: новая партия заменяет только реально присутствующие колонки. Применённые миграции `20260914023000`–`20260914027000` дают private source, hash-идемпотентность, staging до 500 000 строк, server validation, атомарную публикацию, rollback и закрытую объединённую витрину. Публичные RPC ограничивают период, фильтры, сортировку и пагинацию и проверяют кабинетный доступ. Отдельная server-only страница не импортирует V4-store; её release-флаг остаётся выключенным до рабочих партий.
