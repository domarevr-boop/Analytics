# Клиентский опыт: серверный контур отзывов

## Граница архитектуры

- Только отзывы и связанные с ними агрегаты хранятся в Supabase.
- Воронка, реклама, рентабельность, география, точки входа, планы и справочник продолжают работать локально в IndexedDB.
- Отзывы не входят в `DataSnapshot`, `loadAll()` и резервную копию локальной аналитики.
- Связь отзыва с товаром хранит локальный `product.id` и снимок товарных атрибутов без внешнего ключа к облачному справочнику.

## Безопасный импорт

1. Браузер разбирает Excel и показывает маппинг колонок.
2. Исходный файл временно загружается в приватный bucket `cx-review-imports`.
3. Создаётся пакет `review_import_batches` с SHA-256 файла, размером, версией парсера и маппингом.
4. Строки пакетно записываются в реестр, текстовые отзывы, фрагменты и агрегаты пустых оценок.
5. RPC `verify_review_import_batch` сверяет:
   - `всего = текст + пустые + дубликаты + отклонённые`;
   - число текстовых строк равно числу записанных отзывов;
   - число пустых строк равно сумме агрегатов;
   - реестр содержит все принятые строки.
6. Только после успешной сверки исходный файл удаляется из Storage. Метаданные пакета и хеш остаются.
7. При ошибке записи или сверки файл сохраняется для диагностики, пакет получает статус ошибки.

## Правила данных

- Уникальность: `источник + кабинет + ID отзыва`.
- Пустой отзыв — строка без букв и цифр одновременно в полях «Текст отзыва», «Достоинства» и «Недостатки».
- Пустые отзывы не хранятся как тексты: они агрегируются по дате, кабинету, товару и оценке.
- Ответ продавца хранится отдельно и не входит в будущую классификацию клиентского текста.
- `Регион` из текущего отчёта (`ru`, `by`) сохраняется как код страны/локали, а не как географический регион заказов.
- Несопоставленный товар не блокирует импорт: строка сохраняется со статусом `unmatched`.

## Приватность и доступ

- Все CX-таблицы используют RLS и доступны только авторизованному администратору через `public.is_admin()`.
- Bucket приватный; чтение, загрузка, изменение и удаление разрешены только администратору.
- Поле имени автора является персональными данными и не должно выводиться в публичных представлениях.

## Первый аналитический этап

- Миграция `supabase/migrations/20260801020000_client_experience_raw_analytics.sql` добавляет защищённые RPC для сводки, дневной динамики, распределения оценок, проблемных товаров и серверной пагинации отзывов.
- Страница «Клиентский опыт» не загружает весь массив отзывов в браузер: KPI и графики агрегируются в PostgreSQL, таблица получает не более 50 строк за запрос.
- Общие оценки учитывают текстовые и пустые отзывы; метрики ответов продавца считаются только от отзывов с текстом.
- Доступны фильтры периода, кабинета, категории, бренда, склейки, товара и оценки.
- Обзор показывает фактические оценки и негатив без имитации тематической классификации. Темы и CXI включаются только после публикации управляемого словаря и версии классификатора.
- Имя автора намеренно не передаётся на аналитическую страницу.

## Управляемая таксономия

- Миграция `supabase/migrations/20260802000000_cx_taxonomy_settings.sql` создаёт серверные группы тем, темы, ревизии тем, версии словаря, правила и версионируемую конфигурацию методологии.
- Базовые группы `Продукт / Сервис / Результат опыта` и согласованные темы создаются миграцией, но не зашиваются во frontend.
- Опубликованная версия доступна только для чтения. Любое редактирование начинается с создания единственного черновика; правила и ревизии тем копируются из опубликованной версии.
- Переименование темы в черновике не меняет её название в исторической опубликованной версии.
- Техническая вкладка позволяет выбирать тему, добавлять `keyword / phrase / regex / exclusion`, удалять правила черновика и тестировать словарь на одном примере отзыва.
- Публикация черновика намеренно заблокирована до реализации очереди пересчёта: рабочие метрики нельзя переключить на версию, которая ещё не обработала отзывы.
- Формулы `topic score`, динамического веса, вклада, CXI и Problem Index вынесены в `src/features/clientExperience/cxCalculations.ts` и проверяются командой `npm run test:cx`.

## Морфология и контекстные правила

- Миграция `supabase/migrations/20260802010000_cx_lemma_context_rules.sql` добавляет лемматизированный слой отзывов и фрагментов, конфигурацию структурных правил и пакетное сохранение backfill.
- Текст хранится в трёх формах: исходные поля отчёта, очищенный `normalized_text` и `lemmatized_text` с указанием `lemmatization_version`.
- Нормальная форма строится морфологическим анализатором Az на словарях OpenCorpora. Браузерный UMD-runtime и словари около 10 МБ копируются в статические assets при сборке и загружаются лениво через HTTP только при импорте, тесте или backfill.
- `exact_keyword` — совпадение целого очищенного токена; подстроки внутри слова не считаются совпадением.
- `exact_phrase` — буквальная последовательность в очищенном тексте.
- `lemma` — совпадение одного слова по нормальной форме.
- `lemma_phrase` — последовательность нормальных форм.
- `context` — все элементы `required` должны присутствовать, минимум один элемент `anyOf` должен находиться не дальше `maxDistance` токенов от обязательного слова.
- `regex` работает по очищенному тексту; `exclusion` имеет приоритет над положительными совпадениями темы.
- Новые импорты сразу сохраняют все три слоя. Для ранее загруженных отзывов вкладка настроек показывает кнопку «Подготовить леммы» и выполняет возобновляемый backfill пакетами.

## Пакетная классификация и безопасная публикация

- Миграция `supabase/migrations/20260802020000_cx_batch_classifier.sql` добавляет запуски анализа, отметку обработки каждого текстового отзыва и тематические совпадения с перечнем сработавших правил.
- Публикация не переключает рабочий словарь сразу. Черновик блокируется, отзывы обрабатываются пакетами до 250 строк, затем сервер сверяет общее и обработанное количество.
- Только после успешной сверки предыдущая опубликованная версия архивируется, а рассчитанный черновик становится рабочей версией одной транзакцией.
- Прерванный браузерный процесс можно продолжить. До финализации прежняя версия и её результаты остаются рабочими.
- Правила нельзя менять во время активного перерасчёта; процесс можно остановить, исправить словарь и запустить заново.
- Следующий этап — подключить тематические результаты опубликованной версии к обзору, CXI и аналитике товаров.
## Дашборд тем

- Вкладка `Темы` работает только с последней опубликованной версией словаря, для которой пакетная классификация завершилась успешно.
- Общие фильтры периода, кабинета, категории, бренда, склейки, товара и оценки применяются одновременно к обзору, отзывам и тематическому дашборду.
- После публикации даже одной темы сразу доступны покрытие классификации, число упоминаний, средняя оценка, доля негатива, динамика по дням и товары с наибольшим количеством совпадений.
- Черновик не влияет на рабочий дашборд: сначала правило проверяется в настройках, затем словарь публикуется и только после полной сверки заменяет предыдущую версию.
- Серверный агрегат добавляет миграция `supabase/migrations/20260802030000_cx_topic_dashboard.sql`.

## Аспектная тональность

- Правила словаря отвечают только за обнаружение темы. Тональность не нужно вручную назначать каждому правилу.
- Автоматический классификатор ищет тональные леммы в окне шести слов вокруг упоминания темы и учитывает отрицания `не / ни / нет / без`.
- Если якорь темы нельзя сопоставить с лемматизированным текстом, анализируется тональность всего отзыва; это резервный режим для точных и регулярных правил.
- Один отзыв может одновременно иметь разную тональность по разным темам. Оценка звёздами остаётся отдельной справочной метрикой и не подменяет аспектную тональность.
- Проектный словарь хранится в `cx_sentiment_lexicon`, версионируется миграциями и может расширяться доменными словами без изменения тематических правил.
- Если рядом с темой нет тональных слов, совпадение остаётся нейтральным, а тональность темы при отсутствии позитивных и негативных совпадений равна `null`, а не условным `0` или `50`.
- После изменения тематического или тонального словаря необходимо опубликовать новый черновик: пакетная классификация пересчитает все совпадения.
- Базовую схему добавляет `supabase/migrations/20260802040000_cx_aspect_sentiment.sql`, автоматический контекстный расчёт — `supabase/migrations/20260802050000_cx_automatic_sentiment.sql`.

## Детализация тональности

- Показатели `Позитив / Нейтрально / Негатив` на вкладке тем являются интерактивными и открывают боковую панель с отзывами, сформировавшими выбранную долю.
- Выборка всегда наследует тему и общие фильтры периода, кабинета, товара и оценки; в браузер загружается не более 20 отзывов за один запрос.
- Для проверки классификации показываются товар, исходный текст, достоинства, недостатки и список сработавших тематических правил.
- Серверную пагинацию добавляет миграция `supabase/migrations/20260802070000_cx_topic_review_drilldown.sql`.

## Аналитическое рабочее пространство тем

- Добавлена пользовательская вкладка `Методология`: она показывает актуальную опубликованную версию словаря, путь данных, сущности и связи, типы правил, формулы тональности/CXI/Problem Index, фактические пороги и ограничения интерпретации. Вкладка не зависит от аналитических фильтров и не изменяет настройки.

- Миграция `supabase/migrations/20260803000000_cx_topics_workspace.sql` добавляет двухуровневый серверный агрегат: сводку по всем темам и детализацию выбранной темы.
- Сводка показывает приоритеты по существующему `Problem Index`, CXI трёх групп опыта, карту тем, сравнение с предыдущим равным периодом и полную таблицу тем.
- Ось тональности сохраняет принятую шкалу `0–100`; вклад в CXI остаётся неотрицательным и рассчитывается по утверждённой формуле динамического веса темы.
- Цвет риска использует пороги `medium / high` из опубликованной методологии, а не отдельную клиентскую формулу.
- Предыдущий период вычисляется на сервере как непосредственно предшествующий диапазон той же продолжительности. `Δ негатива` — разница доли негативных совпадений в процентных пунктах.
- Причины негатива — частота срабатывания выражений опубликованного словаря в негативных совпадениях темы. Это диагностический слой словаря, а не автоматически извлечённые причинно-следственные формулировки.
- В frontend передаются только агрегаты, максимум четыре примера отзывов и пятнадцать товаров. Полный список отзывов остаётся отдельным пагинированным RPC по 20 строк.
- Миграция `supabase/migrations/20260803010000_cx_topic_timeseries.sql` добавляет независимый серверный временной ряд выбранной темы: день до 45 дней, неделя до 180 дней, далее месяц; пользователь может явно переключить гранулярность.
- Временной ряд одновременно поддерживает максимум две метрики: тональность, упоминания, негатив, позитив, долю отзывов с темой и среднюю оценку. Упоминания кодируются столбцами, остальные показатели — линиями.
- KPI используют те же серверные бакеты для спарклайнов и сравниваются с непосредственно предшествующим периодом равной продолжительности.
- В стандартном режиме карта делится на четыре симметричных квадранта: `Нишевые / Мейнстрим × Позитивные / Негативные`. Граница тональности равна 50, граница распространённости — середине видимого диапазона доли упоминаний. Цвет точки обозначает группу опыта, а не уровень риска.

## Тональность и воспроизводимость

- Тональность темы: `Positive / (Positive + Negative) × 100`. Нейтральные совпадения не участвуют в оценке, но сохраняются в числе упоминаний.
- Доля оценочных упоминаний: `(Positive + Negative) / (Positive + Neutral + Negative) × 100`.
- CXI взвешивает тональность по числу оценочных совпадений. Тема без позитивных и негативных совпадений не получает искусственное значение и не входит в CXI.
- Pipeline разделён на нормализацию, поиск тем, тональность совпадений и агрегацию. Новая формула агрегации не запускает повторную классификацию текстов.
- `cx_dictionary_versions` фиксирует версии словаря, модели тональности и модели агрегации. Совпадение хранит версию модели тональности.
- При публикации словаря совпадения неизменившихся тем переиспользуются вместе с рассчитанной тональностью; повторно анализируются только новые отзывы и новые или изменённые темы.
- В методологии добавлена матрица интерпретации средней оценки и тональности темы. Показатели относятся к разным уровням анализа и могут двигаться в разных направлениях; вывод проверяется по объёму, доле оценочных упоминаний и исходным отзывам.
- Карта тем позволяет независимо выбирать метрики оси X, оси Y и размера пузыря. Названия матрицы показываются только для стандартного режима `доля упоминаний × тональность`; для пользовательских осей разделители рассчитываются по медианам видимых значений.
- Добавлен серверный `get_cx_cxi_summary`: Overall CXI, Product/Service/Result CXI и вклад каждой темы рассчитываются по оценочным упоминаниям для текущего и предыдущего равного периода.
- По умолчанию страница открывает последний календарный месяц, в котором есть отзывы. Полная история запрашивается с сервера только после явного изменения периода пользователем.
- Карта тем в стандартном режиме использует симметричную матрицу `Нишевые / Мейнстрим × Позитивные / Негативные`; разделитель тональности равен 50, разделитель распространённости расположен по центру видимого диапазона доли упоминаний.
- Перерасчёт разделён на два режима. `Полный перерасчёт и публикация` применяется при изменении словаря или логики и создаёт новую опубликованную версию после полной сверки. `Пересчитать диапазон` применяет текущий опубликованный словарь только к отзывам выбранных дат и не затрагивает остальные периоды.
- Диапазонный запуск хранится в `cx_analysis_runs` с `analysis_scope = range`, датами начала и окончания; каждый пакет атомарно заменяет результаты только своих отзывов, а завершение проверяет число обработанных строк.
- Верх страницы тем показывает четыре композитных индекса и темы-драйверы изменения. Таблица тем сортируется по вкладу в Overall CXI и выводит вес в группе, оценочные упоминания, тональность, негатив и изменение вклада.
- Миграция `supabase/migrations/20260803020000_optimize_cx_topics_dashboard.sql` добавляет покрывающие индексы для фильтров и тематических совпадений, отдельный лимит выполнения CX RPC и обновление статистики планировщика. Frontend запускает сводку и временной ряд параллельно и не повторяет начальный запрос после автоматического выбора темы.
