# Клиентский опыт: архитектура и методология

Обновлено: **10 августа 2026**.

## Граница архитектуры

- Только отзывы и производная CX-аналитика хранятся в Supabase.
- Остальные источники Analytics MVP остаются local-first.
- Frontend не загружает полный набор отзывов: используются RPC-агрегаты, диапазонные запросы и пагинация.
- Исходный XLSX загружается во временное хранилище, после подтверждённой записи всех строк удаляется.

## Безопасный импорт

1. Файл парсится и сопоставляется с обязательными колонками.
2. Создаётся import batch с SHA-256, числом строк, версией parser/mapping и исходным диапазоном дат.
3. Нормализованные отзывы записываются пакетами.
4. Дедупликация использует кабинет и исходный `review_id`; повторный импорт идемпотентен.
5. Сервер сверяет ожидаемое и фактическое число строк.
6. Batch получает успешный статус только после сверки.
7. Временный исходный файл удаляется после успешного завершения; при ошибке сохраняется диагностический статус.

## Сущности

- `review_import_batches` — импорт и его контрольные числа.
- raw/normalized reviews — исходный, очищенный и лемматизированный текст.
- topic groups и topics — группы опыта и темы.
- dictionary versions — черновик, опубликованная и архивные версии словаря.
- topic rules — правила обнаружения темы.
- topic matches — связь отзыв ↔ тема с тональностью совпадения и версиями моделей.
- analysis runs — полный или диапазонный перерасчёт, прогресс и проверка публикации.
- aggregate RPC — KPI, временные ряды, CXI, карта, товары и примеры отзывов.

## Словарь тем

Поддерживаются четыре режима:

- `exact_keyword` — буквальное совпадение нормализованного текста;
- `lemma` — наличие нормальной формы слова;
- `lemma_phrase` — последовательность лемм;
- `context` — required/anyOf с ограничением `maxDistance`.

Пример:

```json
{
  "type": "context",
  "required": ["свет"],
  "anyOf": ["мало", "много", "хватать", "достаточно", "недостаточно"],
  "maxDistance": 4
}
```

Правило определяет тему, но не задаёт её тональность.

## Pipeline

1. **Нормализация:** исходный → очищенный → лемматизированный текст.
2. **Поиск тем:** применение опубликованного словаря.
3. **Тональность совпадения:** анализ контекста вокруг найденной темы с учётом отрицаний.
4. **Агрегация:** KPI, временные ряды, CXI, Problem Index и таблицы.

Изменение только формулы агрегации не запускает повторную классификацию текстов. При публикации нового словаря неизменившиеся связи и их тональность переиспользуются; новые или изменённые темы анализируются повторно.

## Тональность

Тональность темы:

`Positive / (Positive + Negative) × 100`.

- Нейтральные совпадения не входят в знаменатель тональности.
- Нейтральные совпадения входят в число упоминаний темы.
- Если `Positive + Negative = 0`, тональность равна `null`, а не `0` или `50`.

Доля оценочных упоминаний:

`(Positive + Negative) / (Positive + Neutral + Negative) × 100`.

Доля негатива:

`Negative / (Positive + Neutral + Negative) × 100`.

Средняя оценка отзыва и тональность темы относятся к разным уровням анализа и могут двигаться в разные стороны.

## CXI

- Overall CXI — взвешенная тональность всех оценочных совпадений.
- Product CXI — темы группы «Продукт».
- Service CXI — темы группы «Сервис».
- Outcome Index — темы группы «Результат опыта».
- Вес темы внутри группы основан на числе оценочных упоминаний.
- Тема без позитивных и негативных совпадений не получает искусственного CXI и не участвует в взвешивании.
- Вклад темы = вес темы × её тональность; изменение вклада сравнивается с предыдущим равным периодом.

## Problem Index

Problem Index используется для приоритизации внимания и объединяет масштаб темы с негативом по опубликованной методологии. Порог риска берётся из версии методологии; frontend не создаёт дополнительную формулу.

## Полный и диапазонный перерасчёт

### Полный перерасчёт и публикация

Используется при изменении словаря, поиска тем, модели тональности или структуры pipeline.

- создаёт analysis run;
- обрабатывает весь доступный набор пакетами;
- допускает продолжение после прерывания;
- публикует новую версию только после полной сверки;
- прежняя версия остаётся рабочей до атомарного переключения.

### Пересчитать диапазон

Используется после импорта новых отзывов.

- применяет текущий опубликованный словарь;
- ограничивается выбранными датами;
- не затрагивает результаты других периодов;
- не создаёт новую смысловую версию словаря.

## Страница «Клиентский опыт»

### Обзор

Оценки, динамика негатива, товары и базовые показатели качества данных.

### Темы

- Initial range — последний месяц с данными.
- Composite indexes: Overall, Product, Service, Outcome.
- Драйверы роста/снижения вклада.
- Что требует внимания по Problem Index.
- Карта тем и полная таблица.
- Детализация выбранной темы: KPI, динамика, причины негатива, примеры и товары.

### Карта тем

Стандартный режим:

- X — доля упоминаний;
- Y — тональность;
- размер — число упоминаний;
- цвет — группа опыта;
- обводка — выбранная тема.

Plot квадратный и делится геометрически по центру на:

- Нишевые · Позитивные;
- Мейнстрим · Позитивные;
- Нишевые · Негативные;
- Мейнстрим · Негативные.

При пользовательских осях разделители строятся по медианам видимых значений, а стандартные названия квадрантов скрываются.

### Динамика темы

- Автогранулярность: до 45 дней — день, до 180 — неделя, далее — месяц.
- Пользователь может выбрать День/Неделя/Месяц вручную.
- Одновременно отображаются максимум две метрики.
- Упоминания — столбцы; тональность, доли и средняя оценка — линии.
- Агрегация выполняется сервером.

### Методология

Содержит определения, формулы, сущности, pipeline, интерпретацию средней оценки и тональности, ограничения и версии словаря/моделей. Любое изменение формулы или интерпретации обновляет эту вкладку и данный документ в том же коммите.

### Настройки

Черновик словаря, тестирование правил, публикация, полный и диапазонный перерасчёт. Черновик не влияет на рабочий dashboard до успешной публикации.

## Ограничения интерпретации

- Нельзя сравнивать крутизну линий на разных шкалах напрямую.
- Тональность нестабильна при малом числе оценочных упоминаний.
- Корреляция темы и оценки не доказывает причинное влияние.
- Вывод проверяется по объёму, доле оценочных упоминаний и примерам исходных отзывов.
- Причины негатива отражают частоту сработавших выражений словаря, а не автоматически доказанную причинность.

## Версионирование и воспроизводимость

- Версия словаря, модели тональности и модели агрегации сохраняется вместе с результатом.
- Опубликованная версия неизменяема.
- Переименование темы в черновике не переписывает историческую версию.
- Новая публикация не становится рабочей до сверки всех целевых строк.
