# Конкурентная аналитика

**Статус:** актуальный контракт local-first страницы V4 и серверного переноса V5. Проверено 9 сентября 2026.

## Назначение и граница

Страница сравнивает бренды и карточки только внутри загруженного конкурентного файла. Показатель «доля среза» не является долей всего рынка. Наш ассортимент определяется совпадением `wb_article` конкурентного файла с `products.wb_sku` локального товарного справочника.

Рабочая страница пока читает локальный снимок V4. В dev-контуре V5 уже применены версионное хранение, атомарный импорт четырёх листов, bounded API всех блоков страницы и RPC для Import UI. Безопасный `.xlsx` parser/Web Worker, preview, прогресс, журнал, ошибки, этапы и скачивание исходника реализованы за выключенным V5-only флагом. Контрольный файл подтвердил состав 8 412 строк. По решению владельца V5 использует фактические Excel-даты 11–12 августа, а legacy-сдвиг V4 на день назад не сохраняется. Строгая локальная сверка пройдена; транзакционный server smoke ожидает явного разрешения на отправку нормализованных строк в удалённый dev-проект. Ручная приёмка, переключение страницы и постоянная партия не выполнялись.

## Путь данных

1. Один Excel-файл передаётся в `parseCompetitorWorkbook`.
2. До записи распознаются и проверяются четыре листа: заказы и воронка, поисковые запросы, склады и остатки, ежедневные позиции TOP‑50.
3. Даты и числа нормализуются по правилам [IMPORTS](IMPORTS.md).
4. Все четыре набора одной транзакцией заменяют соответствующий конкурентный снимок в IndexedDB.
5. Страница читает локальные наборы, агрегирует их в `competitorCalculations.ts` и отображает обзор либо вкладку динамики TOP.

Хранилища IndexedDB: `competitor_funnel`, `competitor_search`, `competitor_stocks`, `competitor_positions`. Их ключи зафиксированы в [IMPORTS](IMPORTS.md).

В V5 один private Storage-файл и одна `import_batch` образуют полную версию четырёх независимых серверных таблиц. Последний опубликованный batch заменяет снимок целиком; ошибка одной секции блокирует публикацию всей партии, а rollback раскрывает предыдущую версию. Применённый read API не отдаёт четыре массива целиком: отдельные RPC ограничивают диапазон, число фильтров, page size и offset для KPI/рядов, брендов, карточек, запросов, остатков и TOP. Точный статус и порядок — в [V5_COMPETITORS_MIGRATION](V5_COMPETITORS_MIGRATION.md).

## Основные правила расчёта

- Абсолютные показатели воронки суммируются за период. `CTR`, CR корзины и CR заказа пересчитываются из агрегированных числителей и знаменателей.
- Средняя цена и медиана покупателя агрегируются с весом по заказам; средняя позиция в поиске — с весом по показам.
- `% выкупа` — взвешенное заказами исходное значение. Он не восстанавливается делением выкупов на заказы, потому что источник может относить колонки к разным когортам.
- Частотность одинакового нормализованного поискового запроса не суммируется между артикулами: используется максимальное повторённое значение и отдельно считается охват карточек.
- Позиция и остаток карточки относятся к последнему доступному снимку, а деньги и воронка — ко всему выбранному периоду.
- Для складской структуры детальные склады одного артикула имеют приоритет над строкой `Маркетплейс`; если детализации нет, используется агрегат. Это исключает двойной счёт.
- Изменение остатков сравнивает первый и последний доступные снимки выбранного периода после применения фильтров брендов и складов.
- TOP‑10/20/50 сравнивается как последовательность доступных дневных снимков без интерполяции пропущенных дат.

## Интерфейс

Обзор содержит фильтры периода, бренда и поиска, KPI «срез / мы», агрегаты брендов, настраиваемый bubble chart, индексную динамику брендов и метрик, таблицу брендов, распределение остатков по складам, детализацию карточек, спрос и покрытие. Вкладка «Динамика TOP‑50» показывает сохранность состава, входы и выходы, присутствие брендов и движение отдельных артикулов.

Встроенная пользовательская методология хранится в `src/pages/analytics/analyticsHelpContent.ts` и обновляется вместе с изменением метрик, фильтров или ограничений страницы.

## Ограничения и проверки

- Полнота конкурентного файла приложением не подтверждается.
- Для динамики и изменения остатков нужны минимум две доступные даты.
- Дни запаса не учитывают будущие поставки, товар в пути и изменение темпа спроса.
- Индексная динамика сравнивает относительное изменение рядов; абсолютные значения остаются в tooltip и таблицах.

Проверки V4: `node --test src/data/competitorCalculations.test.ts`, ESLint затронутых файлов и `npm run build`. Проверки V5: `npm run test:v5-infra`, `npm run db:v5:smoke-competitors-read` и `node scripts/run-supabase.mjs db lint --linked --level warning`. Последний remote smoke подтвердил шесть групп формул и границ с обязательным `ROLLBACK`.
