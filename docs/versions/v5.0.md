# Analytics MVP v5.0

Проверено: **16 сентября 2026**. Статус: **staging, 62 из 69 пунктов текущего roadmap (90%)**. Server-only «Конкуренты» и «Точки входа» приняты в браузере на постоянных dev-партиях; «Поисковые запросы» проверены реальным файлом с rollback, чтение «Географии»/«Воронки» ждёт первые рабочие партии, production остаётся V4.

## Цель

V5 переносит источники, историю импорта, нормализованное хранение и расчёты основных отчётов в отдельный Supabase/PostgreSQL-контур. Страница переносится только законченным сценарием `источник → загрузка → хранение → расчёт → UI`; перенос формулы не совмещается с изменением методологии.

- Import UI показывает последние 20 доступных партий «Рынка» из bounded server RPC: статус, период, счётчики строк/ошибок/попыток и наличие сохранённого исходника. Транзакционный smoke подтвердил журнал для опубликованной, отменённой и отклонённой партий.

- Сохранённый исходник доступной партии можно скачать из Import UI; файл остаётся приватным, а разрешение проверяется журналом партии и Storage RLS.
- Для доступной партии Import UI показывает bounded-хронологию серверных этапов от создания до публикации, отклонения или отмены без раскрытия идентификатора исполнителя.
- Страница «Рынок» подключена к ограниченным RPC за V5-only feature flag. В этом режиме она не читает локальный рынок и явно показывает ошибку Supabase; остальные потребители источника пока не переключены.
- Frontend V5 читает назначенную серверную роль через `v5_my_access`. Не-admin не получает доступ к local-first страницам: viewer видит только серверный «Рынок», importer — также ограниченный импорт этого источника; при выключенном backend feature flag локальный fallback для них не открывается. Полный переходный интерфейс остаётся у admin.
- V5-админка больше не зависит от отсутствующей V4 Edge Function: admin-only RPC перечисляет Auth-пользователей без выдачи service key браузеру, а назначение/отключение роли проходит существующий audit trail. Создание Auth-аккаунтов пока выполняется в Supabase Dashboard.
- Добавлена серверная модель товарных идентичностей: кабинетные seller SKU/WB ID/алиасы, бренды, категории, склейки и датированные состояния состава. Resolver повторяет правило «последнее известное состояние», сохраняя различие между неизвестным составом и явным «Без склейки».
- Миграция `20260911019000` повторяет существующую import-driven механику V4: после полной валидации партия ищет товар по точному/каноническому seller SKU, WB SKU и алиасам, создаёт отсутствующий товар, сохраняет исходные варианты и назначает «Без склейки». Предварительный постоянный каталог и решения по 8 bootstrap-компонентам больше не блокируют страницы.
- Для «Конкурентов» в dev V5 применены версионное хранение, атомарный четырёхсекционный импорт, bounded API страницы и RPC Import UI. Безопасный `.xlsx` parser/Web Worker, preview, прогресс, bounded-журнал, ошибки, этапы и скачивание private-исходника реализованы за V5-only feature flag; remote smoke и `db lint` прошли. Контрольный файл дал 8 405 канонических строк после замены семи точных дублей последними строками. Принято использовать фактические Excel-даты 11–12 августа и не сохранять legacy-сдвиг V4; строгая локальная и серверная транзакционная сверки пройдены с полным rollback. Затем под admin через реальный UI постоянно опубликована партия 8 405/8 405 без отклонений и ошибок, сохранены private-исходник и 20 событий lifecycle; preview, отмена и запрос скачивания проверены, адаптивная компоновка и вложенные параметры журнала исправлены. Осталась отдельная importer-приёмка.

Browser-приёмка постоянной партии завершена: фильтр бренда, сброс, пагинация и вкладка TOP‑50 работают без V4-store; локальная конфигурация по умолчанию остаётся выключенной.

Версионное хранение по кабинетам, RLS, private server import и bounded RPC фильтров/KPI/рядов/локаций/SKU применены в dev V5; remote smoke с rollback и db lint прошли. Реальный файл постоянно опубликован двумя автоматически определёнными кабинетными партиями: 6 593 строки за 18.07.2026, 5 096 «Светпланет» и 1 497 «Ледситипро», создан 401 товар. - Исправлена регрессия кабинетных импортов V5: ручной выбор кабинета удалён для «Географии», «Точек входа» и «Воронки/XWay». - Расширена реальная приёмка XWay: полный смешанный `Xway_data (1).xlsx` содержит 3 568 строк за 01–27.06.2026, все пять метрик и ноль невалидных значений; автоматическая маршрутизация распределила 1 732 строки/65 товаров в «Светпланет» и 1 836 строк/68 товаров в «Ледситипро». ## Следующая граница

Следующая граница — опубликовать и принять под admin первые партии «Географии», «Поисковых запросов» и «Воронки/рекламы». Затем переносится рентабельность, чтобы восстановить финансовые связи без локального fallback. Исторический bootstrap не блокирует страницы; доказанный backup/restore остаётся release-gate надёжности, а ручная ролевая приёмка выполняется единым финальным проходом.
