# UI Components

Краткие контракты переиспользуемых элементов. Визуальные значения и паттерны определяет `DESIGN_SYSTEM.md`.

## `NavBar` analytics menu

- Меню аналитики поддерживает именованные группы и произвольное число ссылок внутри каждой группы.
- Desktop открытие: hover, focus или click; закрытие: уход указателя/фокуса, внешний click или выбор страницы.
- Trigger и пункты меню являются кнопками с `aria-expanded`, `aria-haspopup`, `role="menu"` и `role="menuitem"`.
- Desktop использует три колонки; узкая ширина — одну колонку в пределах viewport.
- Новая аналитическая страница добавляется одновременно в `PageName`, маршрутизацию `App` и нужную смысловую группу `NavBar`.

## `DateRangeFilter`

- Единый контрол диапазона для Dashboard и аналитических страниц.
- Поддерживает presets, custom range, draft-state, apply/cancel и безопасное позиционирование popover.
- На широком экране — два месяца, на узком — один.
- Сравнение строится отдельным контролом или автоматически равным предыдущим периодом, если это закреплено страницей.

## `FilterBar`

- Порядок: период → сравнение → кабинет → категория → бренд/склейка → поиск → дополнительные фильтры → метрики → result count/reset.
- Все видимые controls имеют одну высоту.
- Страница передаёт значения и callbacks; компонент не владеет бизнес-формулами.

## Select

- Один стиль для одиночного выбора метрики, сущности и сортировки.
- Label располагается над контролом только когда без него теряется смысл.
- Ширина зависит от контента, но не растягивает toolbar без необходимости.
- Длинные значения обрезаются с tooltip.

## Segmented Control

- Используется для взаимоисключающих режимов: День/Неделя/Месяц, Товар/Склейка, Заказы/Сумма заказов.
- Активный сегмент использует жёлтый акцент.
- Не заменяет multi-select.

## Metric Picker

- Один metric select — для основной метрики.
- До двух метрик — через два одинаковых select или multi-select с лимитом 2.
- Для bubble/scatter-графика допустимы три компактных select: ось X, ось Y и размер круга. Все три контрола должны оставаться рядом с графиком и синхронно обновлять его заголовок, шкалы, tooltip и легенду размера.
- Выбор визуально отражается в легенде и tooltip графика.
- Повторно используемые таблицы сохраняют выбор колонок.

## KPI Tile

- Label, value, comparison delta, sparkline и optional progress.
- Размеры и порядок одинаковы внутри одного ряда.
- Loading не меняет размер плитки.
- `null` показывается как `—`, отсутствие плана — `Не задан`.

## Analytical Matrix

- Эталон — матрица показателей страницы «Динамика ниши».
- Порядок колонок: сущность/метрика → sparkline → изменение → фиксированные даты → среднее → изменение за период.
- Sticky context columns слева; групповая сущность выводится отдельной строкой над своими метриками.
- Fixed-width date columns не растягиваются при коротком периоде.
- Row-local heatmap по умолчанию.
- Sparkline, delta, среднее и ячейки используют один и тот же период и набор дат.

## Product Cell

- Фото, название, SKU, WB ID и вторичные теги находятся в одной ячейке.
- Фото и SKU кликабельны, если открывают карточку товара.
- Не повторять SKU как название при отсутствии отдельного имени.

## Chart Panel

- Заголовок и краткий вопрос слева; controls справа.
- Legend внутри header или над plot, если не уменьшает полезную область.
- Empty/error/loading занимают ту же высоту, что и график.

## Profitability Controls

- Month strip является быстрым preset для общего `DateRangeFilter`, а не отдельным независимым периодом.
- Monthly expense editor редактирует ставку выбранного месяца отдельно для каждого кабинета.
- Status tabs переключают товарный срез: все, прибыльные, ниже цели, убыточные, без продаж.
- Waterfall показывает формирование чистой прибыли и использует те же агрегированные суммы, что KPI и таблица.

## Topic Map

- Квадратный plot.
- Стандарт: X — доля упоминаний, Y — тональность, size — упоминания, color — группа.
- Selection — отдельная обводка.
- Labels ограничиваются границами plot; полный набор метрик доступен в tooltip.

## `AnalyticsHelp`

- Общий полноширинный режим методологии для самостоятельных аналитических страниц.
- Контент задаётся типизированным объектом: область расчёта, поток данных, руководство по чтению, формулы, группы метрик и ограничения.
- Раскрываемая метрика обязана содержать значение, фактический источник, формулу и интерпретацию.
- Кнопка возврата закрывает справку без сброса состояния исходной страницы.
- Источник компонента: `src/components/AnalyticsHelp.tsx`; контент трёх страниц: `src/pages/analytics/analyticsHelpContent.ts`.
