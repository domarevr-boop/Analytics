# Унификация дизайн-системы Analytics MVP

Статус: **семейство обзорных страниц реализовано, ожидается визуальная приёмка пользователя**.
Текущий этап: **4 — «География», «Конкуренты» и «Отчётность» переведены на принятый общий слой**.
Следующее действие: **пользователь проверяет три опубликованные страницы на 1440/1280 px; до подтверждения этап 5 не начинается**.

Этот документ хранит только ход программы и точки принятия решений. Действующие визуальные правила находятся в [DESIGN_SYSTEM](DESIGN_SYSTEM.md), контракты компонентов — в [UI_COMPONENTS](UI_COMPONENTS.md). После каждого принятого этапа обновляются они, этот статус и проектный навык `skills/analytics-product-design/`.

## Утверждённое направление

- Общий скелет аналитики: заголовок и назначение → глобальные фильтры → KPI → основной ответ → объясняющая аналитика → проверочная таблица. Планирование, импорт, администрирование и методология CX могут использовать специальную структуру.
- Один filter bar: период → кабинет → категория → поиск → дополнительные фильтры → контекст страницы; активные условия показываются chips, общий сброс вторичен.
- KPI имеют анатомию `название → значение → сравнение → дополнительный контекст`; sparkline используется только для реального временного ряда.
- Controls графика находятся в его header. Карточка создаётся только для смысловой группы, без вложенных декоративных рамок.
- Таблицы используют единые заголовки, выравнивание, сортировку чисел, chevron/indent, состояния строк и сдержанную цветовую семантику.
- Плотность задаётся режимами `Overview`, `Analytics` и `Data`; это свойство блока/страницы, а не пользовательский переключатель.
- Жёлтый остаётся фирменным цветом выбора и основного действия; предупреждение получает отдельный янтарный токен. FBO — синий, FBS — бирюзово-зелёный, отдельно от семантического зелёного роста.
- Основной шрифт — Inter; числа используют `font-variant-numeric: tabular-nums` без отдельного JetBrains Mono.
- Макет страницы «Рынок» является первым пилотом. Фиксированные размеры референса, декоративное копирование и изменение бизнес-логики не входят в задачу.

## Этапы

1. **Основа — выполнено** — добавлены совместимые токены и примитивы без массового удаления старого CSS.
2. **Пилот «Рынок» — выполнено в коде** — общий page header, toolbar, KPI, panel/chart header, segmented control, empty-state и плотная проверочная таблица применены без изменения источника и формул.
3. **Приёмка пилота — выполнено** — focused lint, production build и профильные тесты прошли; пользователь подтвердил опубликованную страницу визуально.
4. **Обзорные страницы — принято** — География, Конкуренты и Отчётность используют общие page header, toolbar, KPI и empty-state; их специализированные графики, таблицы и расчёты сохранены. После приёмки в «Отчётность» добавлены фильтры кабинета и категории только для собственных данных.
5. **Аналитические страницы — начато** — «Воронка» переведена на общий page header, toolbar, surface и empty-state; Точки входа, Поисковые запросы и Динамика ниши ожидают миграции после визуальной приёмки «Воронки».
6. **Финансовые и data-heavy страницы** — Главная, Рентабельность, Планирование.
7. **CX и служебные страницы** — клиентский опыт, Импорт, Справочник, Админ, Разработка с учётом их специальных сценариев.
8. **Очистка** — удалять только доказанно неиспользуемые стили после миграции соответствующего семейства; синхронизировать документацию и установленную копию навыка.

## Ограничения и критерии перехода

- Формулы, фильтры, источники, импорт и хранение данных не меняются в рамках визуальной миграции.
- Не выполнять big-bang переписывание `App.css`; старые правила удаляются только после проверки их потребителей.
- Новая общая абстракция сначала подтверждается на «Рынке» и только затем распространяется на другие страницы.
- На уровне страницы не должно быть горизонтального overflow; прокрутка сложной таблицы допускается внутри её поверхности.
- Обязательны keyboard focus и состояния loading, empty, error, hover, selected, expanded и disabled.
- Этап считается завершённым после автоматических проверок, визуального подтверждения пользователя и обновления этого документа.

## Реализованный технический слой

- Токены и общие стили: `src/styles/design-system.css`.
- Примитивы аналитики: `src/components/AnalyticsPrimitives.tsx`.
- Пилот: `src/pages/analytics/MarketPage.tsx` и `MarketPage.css`.
- Источник «Рынка» не содержит кабинетов, категорий, товаров и FBO/FBS: неработающие фильтры из референса в пилот не добавлены.
- Проверено: focused ESLint, `npm run build`, `node --test src/data/marketCalculations.test.ts` — успешно.
- Этап 4: добавлен совместимый слой `src/styles/overview-pages.css`; focused ESLint и production build прошли, профильные тесты географии, конкурентов и отчётности — 21/21.
- Этап 5: аналитическое семейство продолжает совместимый слой `src/styles/overview-pages.css`; первой репрезентативной страницей выбрана «Воронка», её формулы, фильтры и специализированные блоки не менялись.

## Режим работы агентов

- Основа, пилот и изменения общего контракта выполняются Sol с высоким reasoning и предварительным аудитом.
- Luna `xhigh` подходит для последующей механической миграции уже утверждённого паттерна на независимые страницы.
- Параллельная работа допустима только для независимых страниц после пилота; общие токены, компоненты и документацию изменяет один агент-интегратор.
- После сжатия контекста агент начинает с `AGENTS.md`, `PROJECT_STATE.md`, этого документа, `DESIGN_SYSTEM.md`, `UI_COMPONENTS.md` и `git status`, затем продолжает с указанного текущего этапа.
