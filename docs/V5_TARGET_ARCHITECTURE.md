# Целевая модель Analytics V5

Проверено: **10 сентября 2026**. Документ переводит три согласованные визуальные карты развития, инфраструктуры и методологии в проверяемые границы V5. Карты задают целевое состояние; они не подтверждают, что перечисленные возможности уже реализованы.

## Граница версии

V4 — рабочий local-first прототип, который показывает данные. V5 должна стать единой аналитической системой: систематизировать источники, хранить очищенные данные централизованно, воспроизводимо рассчитывать основные модули и поддерживать регулярное использование небольшой командой.

Полноценные внешние API, AI-copilot и глубокая интеграция в бизнес-процессы относятся к V6. Сеть агентов, самостоятельный мониторинг отклонений и перенос части процессов с измеримым эффектом относятся к V7. В V5 допускаются только ограниченные API-пилоты и автоматизация загрузок, не расширяющие продукт до V6.

Критерий завершения V5: согласованные ключевые сценарии работают на реальных централизованных данных, регулярно обновляются, дают воспроизводимый результат и приняты командой. Наличие схемы, миграции или демонстрационного UI само по себе этот критерий не закрывает.

## Целевая инфраструктура

1. **Источники:** отчёты и будущие API WB, XWay/реклама и финансовые файлы. Для каждого источника сохраняется резервный ручной путь CSV/XLSX, пока автоматический канал не доказал надёжность.
2. **Серверная обработка:** Supabase принимает исходник или API-пакет, валидирует и нормализует строки, выполняет версионированные расчёты и агрегаты, ведёт журнал ошибок и планирует регулярные обновления.
3. **Единый слой данных:** PostgreSQL/Supabase является источником истины для очищенных данных, справочников и временных связей, истории загрузок и версий методологии.
4. **Клиент:** React + TypeScript + Vite получает только защищённые bounded-выборки, агрегаты и страницы данных. Локальное хранение допустимо как кэш, но не как источник истины V5.
5. **Доставка:** исходный код хранится в GitHub, frontend собирается и публикуется отдельно от V4, браузеры команды работают по HTTPS и серверным ролям.

Контур надёжности обязателен для V5: единый источник истины, контроль качества партий, базовое резервное копирование с доказанным восстановлением, журнал ошибок и роли `viewer / importer / admin`. Планировщик обновлений становится обязательным только для тех источников, чей автоматический канал принят в V5.

## Целевая методология

Каждый переносимый сценарий описывается одной трассируемой цепочкой:

`бизнес-вопрос → источник и владелец → гранулярность и период → показатель и формула → обработка и версия правил → аналитическая модель → результат → интерпретация и действие`.

Минимальный паспорт сценария содержит:

- роль пользователя, бизнес-вопрос, решение и периодичность;
- каталог источников, владельца, гранулярность, период обновления, правила объединения и ограничения данных;
- словарь показателей: смысл, формулу, источник полей, единицу анализа и допустимые фильтры;
- валидацию, очистку, справочники, агрегацию и версию правил;
- связи с продажами, воронкой, экономикой, рекламой, рынком, географией и CX только там, где они доказаны данными;
- правила сравнения, пороги, диагностические подсказки и связь с бизнес-действием;
- владельца методологии, дату пересмотра и историю изменений.

Методология зрелая, когда показатель прослеживается до источника, одинаковый расчёт даёт одинаковый результат, изменения правил версионируются, ограничения понятны пользователю, а расчёт не зависит от памяти автора.
