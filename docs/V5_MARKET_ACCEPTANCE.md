# Приёмка пилота V5 «Рынок»

Проверено: **7 сентября 2026**. Автоматические проверки backend, parser и production build пройдены. Этот документ фиксирует оставшуюся ручную проверку; до её завершения пилот не считается принятым и downstream-страницы не переключаются на V5.

## Условия перед началом

- Работать только в `C:\Users\vipdo\Documents\test\Analytics-v5`, ветка `v5/backend-foundation`.
- `.env.local` должен содержать `VITE_APP_ENV=v5-development`, URL/publishable key отдельного V5-проекта и `VITE_V5_MARKET_BACKEND_ENABLED=true`. Значения ключей не копировать в отчёт о приёмке.
- Запуск: `npm run dev -- --host 127.0.0.1`. V5 не публикуется; проверка выполняется локально.
- Нужны три отдельных Auth-пользователя V5: admin, importer и viewer. Пользователей создаёт владелец в Supabase Dashboard V5 → Authentication → Users; роли назначаются администратором на странице «Админ» V5. Реальные адреса и UUID в документ не записываются.
- Использовать доверенный отчёт «Рынок» `.xlsx` или `.csv`. До проверки сохранить отдельную копию файла.

## Сценарий A — администратор и importer

1. Войти как admin и проверить, что доступны переходные страницы, «Админ» и «Импорт»; в каталоге пользователей назначить второму аккаунту роль `importer` со статусом «Активен».
2. Войти как importer в отдельном профиле браузера. Ожидание: доступны только серверный «Рынок» и ограниченный импорт V5; локальные страницы и управление доступом скрыты.
3. Загрузить контрольный файл «Рынок». Зафиксировать имя файла, период, число исходных строк, принятых и отклонённых строк; секреты, UUID пользователей и содержимое `.env.local` не фиксировать.
4. В истории партии открыть «Этапы». Ожидание: хронология начинается созданием партии и заканчивается публикацией; число строк и период согласуются со сводкой.
5. Нажать «Скачать» и сравнить скачанный файл с исходным по имени, размеру и содержимому. Публичная ссылка появляться не должна.
6. Открыть страницу «Рынок» и выбрать тот же период. Сверить сумму рынка, наши заказы, количества заказов, доли и средние чеки с V4/контрольным файлом. Допускается только заранее объяснённое различие; формулы в ходе переноса не исправляются.
7. Повторно загрузить тот же файл. Ожидание: возвращается существующая опубликованная партия, факты и число дней не удваиваются, в истории не появляется вторая опубликованная версия тех же данных.

## Сценарий B — ошибочный файл

1. На копии файла испортить одно обязательное числовое значение или дату и загрузить её как новый файл.
2. Ожидание: партия получает статус «Отклонён», рабочая страница «Рынок» не меняется.
3. Открыть «Ошибки». Должны быть видны лист, строка, колонка, код, причина и исходное значение повреждённой ячейки.
4. Открыть «Этапы». Хронология должна заканчиваться статусом `failed`, а исходник — оставаться доступным для скачивания.

## Сценарий C — viewer и изоляция

1. Как admin назначить третьему аккаунту роль `viewer` со статусом «Активен».
2. Войти как viewer в отдельном профиле браузера. Ожидание: доступна только серверная страница «Рынок»; «Импорт», «Админ» и local-first страницы скрыты.
3. Попытка открыть URL импорта или админки вручную должна перенаправлять на разрешённую страницу, а не показывать переходные локальные данные.
4. Вернуться под importer. Он должен видеть только созданные им/явно разрешённые партии; admin видит все партии. Проверка считается окончательно пройденной только с отдельными реальными аккаунтами, а не сменой роли одного пользователя.

## Критерий принятия и доказательства

Пилот принят, когда все три сценария выполнены без необъяснённых расхождений. В задаче/журнале сохранить дату проверки, версию commit, название и период контрольного файла, контрольные итоги V4/V5, результат повторной загрузки, результат ошибочной загрузки и подтверждение матрицы ролей. Пароли, токены, ключи и UUID пользователей не сохранять.

При ошибке выключить локальный `VITE_V5_MARKET_BACKEND_ENABLED`, прекратить новые V5-импорты и сохранить идентификатор партии из UI для диагностики. V4 и production не переключаются и не требуют отката. Отменять опубликованную партию разрешается только после определения точного batch ID и причины; восстановление данных выполняется новой версией/партией, а не удалением истории.
