# Приёмка пилота V5 «Рынок»

Проверено: **7 сентября 2026**. Автоматические проверки backend, parser и production build пройдены. Этот документ фиксирует оставшуюся ручную проверку; до её завершения пилот не считается принятым и downstream-страницы не переключаются на V5.

## Условия перед началом

- Работать только в `C:\Users\vipdo\Documents\test\Analytics-v5`, ветка `v5/backend-foundation`.
- `.env.local` должен содержать `VITE_APP_ENV=v5-development`, URL/publishable key отдельного V5-проекта и `VITE_V5_MARKET_BACKEND_ENABLED=true`. Значения ключей не копировать в отчёт о приёмке.
- Проверка выполняется на staging `https://domarevr-boop.github.io/Analytics/v5/` либо локально через `npm run dev -- --host 127.0.0.1`; оба варианта должны использовать отдельный Supabase V5.
- Для текущей функциональной приёмки достаточно admin. Отдельные Auth-пользователи importer и viewer потребуются в едином финальном ролевом gate после функционального переноса страниц; их создаёт владелец в Supabase Dashboard V5 → Authentication → Users, а роли назначаются на странице «Админ» V5. Реальные адреса и UUID в документ не записываются.
- Использовать доверенный отчёт «Рынок» `.xlsx` или `.csv`. До проверки сохранить отдельную копию файла.

## Сценарий A — функциональная приёмка под admin

1. Войти как admin и проверить, что доступны переходные страницы, «Админ» и «Импорт».
2. Загрузить контрольный файл «Рынок». Зафиксировать имя файла, период, число исходных строк, принятых и отклонённых строк; секреты, UUID пользователей и содержимое `.env.local` не фиксировать.
3. В истории партии открыть «Этапы». Ожидание: хронология начинается созданием партии и заканчивается публикацией; число строк и период согласуются со сводкой.
4. Нажать «Скачать» и сравнить скачанный файл с исходным по имени, размеру и содержимому. Публичная ссылка появляться не должна.
5. Открыть страницу «Рынок» и выбрать тот же период. Сверить сумму рынка, наши заказы, количества заказов, доли и средние чеки с V4/контрольным файлом. Допускается только заранее объяснённое различие; формулы в ходе переноса не исправляются.
6. Повторно загрузить тот же файл. Ожидание: возвращается существующая опубликованная партия, факты и число дней не удваиваются, в истории не появляется вторая опубликованная версия тех же данных.

## Сценарий B — ошибочный файл

1. На копии файла испортить одно обязательное числовое значение или дату и загрузить её как новый файл.
2. Ожидание: партия получает статус «Отклонён», рабочая страница «Рынок» не меняется.
3. Открыть «Ошибки». Должны быть видны лист, строка, колонка, код, причина и исходное значение повреждённой ячейки.
4. Открыть «Этапы». Хронология должна заканчиваться статусом `failed`, а исходник — оставаться доступным для скачивания.

## Сценарий C — финальный ролевой gate viewer/importer/admin

1. Как admin назначить отдельным аккаунтам роли `importer` и `viewer` со статусом «Активен».
2. Войти как viewer в отдельном профиле браузера. Ожидание: доступны только перенесённые серверные страницы; «Импорт», «Админ» и local-first страницы скрыты.
3. Попытка открыть URL импорта или админки вручную должна перенаправлять на разрешённую страницу, а не показывать переходные локальные данные.
4. Войти как importer. Ожидание: доступны перенесённые серверные страницы и только разрешённые импорты; управление доступом и local-first страницы скрыты.
5. Importer должен видеть только созданные им/явно разрешённые партии; admin видит все партии. Проверка считается окончательно пройденной только с отдельными реальными аккаунтами, а не сменой роли одного пользователя.

## Критерий принятия и доказательства

Функциональный пилот принят, когда сценарии A и B выполнены без необъяснённых расхождений. Релизная ролевая приёмка завершается сценарием C после переноса страниц. В задаче/журнале сохранить дату проверки, версию commit, название и период контрольного файла, контрольные итоги V4/V5, результат повторной загрузки, результат ошибочной загрузки и позднее — подтверждение матрицы ролей. Пароли, токены, ключи и UUID пользователей не сохранять.

При ошибке выключить локальный `VITE_V5_MARKET_BACKEND_ENABLED`, прекратить новые V5-импорты и сохранить идентификатор партии из UI для диагностики. V4 и production не переключаются и не требуют отката. Отменять опубликованную партию разрешается только после определения точного batch ID и причины; восстановление данных выполняется новой версией/партией, а не удалением истории.
