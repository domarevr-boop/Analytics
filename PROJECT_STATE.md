# Текущее состояние Analytics MVP

Обновлено: **30 августа 2026**.

## Активная версия

- Рабочая версия: **v4.0**.
- Следующая продуктовая версия: **новая v5.0**. Её наполнение ещё не сформировано; зарезервирован URL `/Analytics/v5/`.
- Эксперимент серверной миграции основных отчётов не является активным направлением.
- Текущий этап — стабилизация v4.0 и сокращение числа источников документации; новых архитектурных миграций не запланировано.

## Архитектура

- Клиент: React 19 + TypeScript + Vite.
- Основные отчёты, планы, справочник и вычисляемые витрины работают local-first в браузере; «Отчётность» объединяет собственные локальные данные с агрегированным локальным отчётом «Рынок».
- Отзывы покупателей — отдельный серверный контур Supabase: импорт, дедупликация, таксономия, тональность, CXI, агрегаты и пагинация.
- Исходные файлы отзывов не хранятся постоянно: после пакетной записи и сверки числа строк временный объект удаляется.
- GitHub Pages публикует статический frontend. Секреты Supabase не должны попадать в клиентскую сборку; доступ регулируется RLS и RPC.

## Реализованные рабочие разделы

- Главная: месячные KPI, иерархическая таблица, планы, финансовые показатели, рекламные и воронковые метрики, связанные графики.
- Импорт: распознавание источников, точечная замена метрик, кабинетно-безопасное обновление, покрытие данных.
- Планирование, рентабельность, справочник товаров и изображения.
- Аналитика: воронка, точки входа, география заказов, поисковые запросы WB, рынок, динамика ниши, конкуренты и «Отчётность». «Рынок» хранит ежедневные суммы и количество заказов, доли и средние чеки; его средний чек используется для денежной оценки поискового спроса. «Отчётность» сравнивает равные периоды, показывает собственные KPI и рынок, а также детализацию собственных показателей по кабинетам. Страница конкурентов использует локальный атомарный импорт четырёх листов Excel, сравнивает срез с нашим ассортиментом, анализирует многосерийную динамику и складские снимки, отдельно отслеживает структуру TOP‑10/20/50.
- Карточка товара: общие KPI, динамика, воронка, источники трафика и география.
- Клиентский опыт: обзор, отзывы, темы, методология и настройки анализа.

## Клиентский опыт

- Темы определяются опубликованным версионируемым словарём: `exact_keyword`, `lemma`, `lemma_phrase`, `context`.
- Тональность определяется отдельно от поиска темы и хранится на уровне совпадения.
- Тональность темы: `Positive / (Positive + Negative) × 100`; при отсутствии оценочных упоминаний возвращается `null`.
- CXI рассчитывается по оценочным упоминаниям и разделён на Overall, Product, Service и Outcome.
- Доступны полный перерасчёт при изменении логики и диапазонный перерасчёт для новых дат.
- Начальный период страницы — последний месяц, в котором есть данные.

## Канонические правила UI

- Главная задаёт эталонный контракт фильтра периода и сущностей.
- KPI выводятся отдельными плитками с единым строением.
- Плотные временные таблицы используют фиксированный левый контекст и фиксированную ширину колонок дат.
- Выбор метрик, select и segmented controls переиспользуют общие визуальные контракты.
- Текущая дизайн-система: `docs/DESIGN_SYSTEM.md`; компоненты: `docs/UI_COMPONENTS.md`.

## Активные ограничения

- Большая часть данных зависит от IndexedDB конкретного браузера и не синхронизируется между устройствами.
- Версия локальной IndexedDB изменяется только монотонно; текущая схема — 9, где добавлено отдельное хранилище `market_dynamics`.
- Рост локальной базы требует диапазонных выборок, кэша агрегатов и виртуализации таблиц.
- План ДРР и рекламного бюджета пока не имеет единого месячного источника.
- Подтверждённая рекламная атрибуция точек входа сейчас не реализована и не назначена будущей версии.
- Массовое объединение поисковых запросов WB и продавца остаётся замороженным backlog из-за объёма данных.
- Доля на странице «Конкуренты» ограничена составом загруженного файла и не должна называться долей всего рынка; наш ассортимент определяется по совпадению WB ID со справочником.
- География поддерживает общий фильтр «Все / FBO · Склад WB / FBS · Маркетплейс». FBO и FBS собираются из соответствующих локальных и нелокальных колонок отчёта только внутри расчётов; локальность не является UI-срезом. Сумма и прибыль по типу остаются пропорциональной атрибуцией к общему `orders_total`, потому что исходный отчёт не содержит раздельных денежных полей; покрытие FBO/FBS показывается отдельно.
- Отчёт «Рынок» не содержит измерений кабинета, категории, бренда или товара; «Отчётность» не применяет к нему фиктивные entity-фильтры и не распределяет рынок по кабинетам.

## Документация и рабочие копии

- Единственная актуальная карта документов — `docs/INDEX.md`; незавершённые задачи хранятся только в `docs/ROADMAP.md`.
- История и отменённые эксперименты находятся в `docs/archive/` и не являются действующими требованиями.
- Живое состояние определяется `origin/main`. Соседние Git worktree могут содержать старые ветки и незакоммиченные эксперименты; перенос из них допускается только после отдельного сравнения с `origin/main`.
